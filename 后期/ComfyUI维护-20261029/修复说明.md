# ComfyUI 故障排查与修复 · 2026-10-29

## 结论

反复出现的 MCP 校验超时、提交后报错，并不等于 ComfyUI 生成失败。主要复现点是 CLI 启动上下文不能写默认缓存和 jobs 目录。已修复其本地状态落盘；当前连接的 MCP 已通过校验、提交、完成查询和下载输出的实测。ComfyUI 核心、模型、CUDA、torch、已选素材均未更新。

## 证据与修法

- 核心服务 `http://127.0.0.1:8188` 正常，0.39.0；前端 1.53.10 与核心要求一致。CLI 1.22.0、MCP 0.10.0。
- 原 CLI 校验在 `cql/loader.py → file_utils._atomic_write → tempfile.mkstemp → os.open` 停留。直接写探针复现 PermissionError；Python 临时文件实现会在该情形反复重试，导致工具超时。
- 默认缓存 `C:/Users/36322/.cache/comfy-cli` 和任务记录 `C:/Users/36322/AppData/Local/comfy-cli/jobs` 写入失败；同一工具可写自己的 runtime。PowerShell、直接系统 Python、IndexTTS Python 可写相同目标。这是执行上下文差异证据，尚未进一步证明底层 Windows 拒绝来源；没有修改 ACL、关闭安全措施或声称目录本身损坏。
- 换 Python 3.12.12 基础解释器仍失败，已回滚；`pyvenv.cfg` 与备份 SHA256 相同。另存诊断环境 `C:/Users/36322/.codex/runtimes/comfy-repair-probe`，未接入生产。
- `repair_cli_launcher.py` 保留原虚拟环境与全部包，只为 Comfy MCP 使用的 `Scripts/comfy.exe` 增加启动适配：缓存默认写 `runtime/local-state/cache`，jobs 写 `runtime/local-state/jobs`。旧 JSON 已复制，原目录未删除。外部配置和凭据路径不变。**这是本地启动适配，不是上游官方修复；升级 comfy-cli 可能覆盖，需要复测或重放脚本。**
- 输出下载先落在该运行目录，再通过正常文件工具复制到作品目录；并不声称原启动上下文现在可写任意目录。
