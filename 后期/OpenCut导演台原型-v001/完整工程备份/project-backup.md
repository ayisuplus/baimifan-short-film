# 完整工程备份与恢复

编辑器右上角和工程列表页均有「工程备份」。保存时暂停播放，把已保存时间线、素材原文件、剧本、灵感与设定、基础资产版本、参考资料包及已有超分记录一起写入磁盘。当前窗口的文字草稿单独收录，恢复后仍需手动保存。整个过程不调用生成服务，不提交或恢复 GPU 任务。

## 使用

1. 在工程中打开「工程备份」，点击「保存当前工程的完整备份」，等待“完整备份已保存”。
2. 对话框显示实际目录。一个 UUID 文件夹就是一份完整备份，必须整目录复制；可放到另一块磁盘。`pending` 里的未完成任务不是有效备份。
3. 浏览器工程丢失后，打开 `/projects` →「工程备份」，选备份并点击「恢复为独立副本」。其他磁盘的备份先整目录放回界面所示备份目录，再刷新列表。
4. 恢复成功后点击「打开恢复副本」。不会覆盖原工程。恢复副本的剧本和资产目录也独立，不向原作品目录保存。

默认备份目录：OpenCut 根目录 `.local/project-backups/`。恢复工作稿在其中的 `restored/<projectId>/`，`registry/` 记录归属；这些是正在使用的副本数据，不能作为临时缓存删除。完整备份是独立 UUID 文件夹，可搬到不同位置，不需要原素材目录存在。安装/启动相同工程格式版本的 OpenCut 后，复制回备份目录即可恢复。媒体不会上传到外网。

## 格式与失败行为

- `manifest.json`：格式版本、原工程身份、时间及每个文件的字节数/SHA-256。
- `browser.json`：全部场景和轨道、字幕内容与隐藏状态、参数/书签/剪辑位置、全部媒体元数据、候选与占位关联、独立文字草稿。
- `browser-media/`：全部浏览器素材实际文件，包含未采用候选、恢复初始版本所需媒体和占位 PNG。读取元数据清单后逐个核对，不能静默跳过丢失文件。
- `creative/`：剧本和文稿版本历史、基础资产原图/版本/来源、已有超分任务资料、旧稿溯源。`package/` 保留参考快照与声音原文件。
- Rust 管理完整性、引用验证、稳定身份重映射、路径边界和发布；Web 只传输文件、操作浏览器存储与展示状态。
- 备份先进入 pending，所有文件校验后才发布；期间时间线、媒体、草稿或原生文稿版本变化会中止本次备份。原工程保留。
- 恢复先验证清单，再创建新 project/package 身份；镜号、片段 ID、素材 ID、版本 ID 和时间关系保留。归属标记重新建立，历史来源文本不改写。
- 浏览器二进制先写入，最后发布工程。存储空间不足、哈希不符或草稿写入失败均不会报告成功；撤销本次原生登记并清理本次媒体。副本目录丢失时严格报错，不回落到原作目录。
- 本地媒体上传与服务端下载采用流；浏览器 SHA-256 核验按单文件读取，因此峰值内存与最大单文件有关，尚未做多 GB 单文件压力验收。

备份不包含应用程序、GPU 模型、API 密钥、浏览器撤销栈、其他窗口尚未保存的草稿或系统字体。字体名称和样式保留，换机器仍需安装对应字体。暂不打包依赖外部服务的声音库 URL 或贴纸；检测到这类时间线依赖会明确拒绝“完整备份”，需先转为本地素材。本轮未改变这类素材。
