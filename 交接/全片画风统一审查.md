## 四、必须提醒的一个风险：Codex 与 Qwen 混编

中段关键帧原先是 Qwen（v032）出的，头尾也是 Qwen（v034），只有 **077 和 085 现在换成了 Codex 版**。

两者同属"手绘二维"一族，但渲染质感不同：Qwen 偏笔刷厚涂与体积光，Codex 偏强墨线平涂、图形化构造。后果是：

> 如果只把 090b 等几张换成 Codex，而水龙段的 078 / 080 / 081 / 083 仍是 Qwen 笔刷水龙，**077（Codex 平涂水龙）反而会成为水龙段里最跳的一张**。

两条可选路径：

- **甲：同族修硬偏离**（本轮默认）。只重画 P0 四张，接受 077 与邻镜存在细微笔触差。快、便宜、不动已通过的构图。
- **乙：整段换渲染**。把中段涉水与变龙关键帧（约 15–20 张）全部用同一 Codex 模板重画，中段自成一体。贵（每张一次 codex 生图），彻底。

**我的建议：走甲，但把水龙段一起做。** 至少让 070 / 074 / 077 / 078 / 080 / 081 / 083 用同一模板，否则 077 是孤岛。这条需要作者定。

## 五、关键边界：改关键帧 ≠ 改成片

- 中段已有成片素材：`后期/` 下 598 个 mp4、`OpenCut后续画面-v018/逐镜视频/` 116 个，这些是**已经渲染出来的画面**。
- 关键帧只是"视频生成的输入"。关键帧画风统一了，**中段成片画面不会自动变统一**。
- 要真正统一中段成片，必须重跑中段视频——那需要解除 `当前制作状态.json` 的 `status=archived` 闸门（只认 `active`）、等 Blender 释放显存，或走 RunningHub 远程生成并消耗额度（余额 24.68 元 / 3400 积分）。本项目已于 2026-11-03 定档，见[定档说明](定档说明.md)。

**所以本轮的实际产出是"中段关键帧层面的画风统一 + 为将来重跑定好基准"，不是成片画风已统一。**

本机 `BaiduNetdisk` 在同步本工作区，Codex 把 PNG 写进 `codex-keyfix/` 时被同步进程占用：

- 090b 首次写入被截断成 189KB 坏文件 → Codex 执行的 PowerShell 命令里带完整 base64 且留在日志，
  **没有重新生成**，改用 `recover_png.py` 从日志重建，文件完整（1674×939）。
- 074 与 065b 改成分块追加写入，中途也是残缺 → 追加完成后文件自然完整；
  `recover_png.py` 另带"按首个 IEND 截断"逻辑处理重复追加。
- 062b 写不进目标目录（权限被拒），Codex 把原图留在自己的缓存
  `C:\Users\36322\.codex\generated_images\...` → 从缓存取回，文件完整。

**后续写图的正确做法**：让 Codex 输出到同步目录之外（或直接用它的 `generated_images` 缓存），再移入工程。
`recover_png.py` 已能处理这两种情况。
